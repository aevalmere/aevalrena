# tools/spritemaker

Wrapper CLI around the **claude-code-sprite-maker** engine, used to build every
Aeval frame from `art/aeval/frames/<anim>/<anim><N>.txt` text sources.

## The plugin

- Repo: https://github.com/bijeebuss/claude-code-sprite-maker
- Cloned and built at: `C:/Users/light_095j4re/Documents/claude-code-sprite-maker`
  (`npm install && npm run build` there; the wrapper needs `build/lib/*.js`
  and the plugin's own `node_modules/sharp` and `node_modules/pngjs`).
- `config.json` next to this README holds `pluginRoot`. Change it if the clone
  moves.
- The plugin is a Claude Code plugin with an MCP server (`build/index.js`)
  exposing `init_frame`, `set_pixel`, `set_row`, `set_frame`, `finalize_frame`,
  `read_reference_image`, `assemble_spritesheet`, `generate_gif`, `flip_frame`.
  Its own slash command only makes 4-direction 16x16 walk cycles, so this
  wrapper drives the library directly but keeps the plugin's frame JSON
  format, so its MCP tools still work on our `.json` frames.
- To load the plugin interactively:
  `claude --plugin-dir C:/Users/light_095j4re/Documents/claude-code-sprite-maker`

Nothing is installed inside the aevalrena repo. The wrapper loads the plugin's
built library and its `sharp`/`pngjs` through `pathToFileURL` + `createRequire`.

## Frame contract (from `art/aeval/PROMPT.md`; do not change without the owner)

- Canvas: **80 wide x 80 tall**, every frame, body and effect alike.
  x runs 0..79 left to right, y runs 0..79 top to bottom.
- **Every frame faces RIGHT.** The renderer mirrors for left.
- **Body centre column: 40.** Columns 0..39 are behind her, 40..79 in front.
- **Heel line: row 67.** Standing feet rest ON row 67. Rows 68..79 are ground
  room for splashes, puddles and down-air spikes only.
- **Standing height: 48 px** from the tallest hair spike (row 20) to the heel
  line (row 67). Head plus hair is about half of that.
- Body about 26 px wide, hair cloud up to about 34 px wide; neutral pose sits
  between columns 24 and 56. Water may reach any pixel.
- Airborne poses tuck the feet up; the body never moves up as a whole.
- Effect frames use the same canvas with the origin at (40, 40).
- Source of truth is the `.txt`: exactly 80 lines of exactly 80 characters.
  `.` is transparent; every other character must be a key in
  `art/aeval/palette.json`. No header, no blank lines, no spaces, no tabs.
- `.json` and `.png` next to each `.txt` are generated by `render`. Never
  hand-edit them (`.json` is git-ignored, `.png` is regenerated).

## Palette: `art/aeval/palette.json`

```
{ "transparent": ".",
  "keys": { "#": "#0e0c16", "c": "#4b4f6b", ... },
  "ramps": { "ink": [...], "coat": [...], "hair": [...], "band": [...], "skin": [...],
             "blush": [...], "eye": [...], "shirt": [...], "boot": [...], "water": [...] },
  "water": ["Q","A","a","q","z"] }
```

Body ramps are listed light to dark (lowercase lighter, uppercase darker
within a pair). The water ramp is listed deep to near-white. Water keys are
never used on the body and body keys never on water: the renderer's outline
ring skips the `water` list. Ink is `#0e0c16`, not pure black, because the
plugin's GIF encoder treats `#000000` as the transparent colour.

## Subcommands

All paths are relative to the repo root unless absolute. Every command prints
what it wrote; errors print `ERROR: ...` and exit non-zero. Validation
problems print `PROBLEM <file> line <n>[ col <x>]: ...` (line is 1-based,
col is the 0-based x of the frame) and exit 1.

| command | what it does | example |
|---|---|---|
| `render <dir>` | validates every `*.txt` in the folder (sorted by trailing number), writes `<name>.json` (plugin FrameData) and `<name>.png` (80x80 RGBA) next to each valid one | `node tools/spritemaker/sm.mjs render art/aeval/frames/idle` |
| `preview <anim>` | 6x contact sheet of `frames/<anim>/*.png`, 4 per row, 8 px grid, heel band on row 67, centre band on column 40, names above each frame; writes `art/aeval/sheets/<anim>_preview.png` | `node tools/spritemaker/sm.mjs preview idle` |
| `preview <anim> --frame N` | one frame at 10x with the same guides; writes `art/aeval/sheets/<anim><N>_big.png` | `node tools/spritemaker/sm.mjs preview idle --frame 0` |
| `gif <anim> [--holds a,b,...]` | 4x animated GIF (320x320) with per-frame holds in sim frames (60/s, default 8 each); writes `art/aeval/sheets/<anim>.gif`. Frames are flattened onto `#1b1d2b` | `node tools/spritemaker/sm.mjs gif idle --holds 8,8,8,8` |
| `stage <anim>` | 640x360 true-scale mock: sky gradient, platform top at y=250, frame 0 at 1x facing right at x=200 and mirrored at x=440 with the heel line on the platform, plus a 3x copy top-right; writes `art/aeval/sheets/<anim>_stage.png` | `node tools/spritemaker/sm.mjs stage idle` |
| `flip <in.png> <out.png>` | mirror a PNG horizontally (sharp `.flop()`) | `node tools/spritemaker/sm.mjs flip a.png a_left.png` |

`gif` uses a temp folder under `art/aeval/sheets/.tmp/` and removes it when
done. Because the plugin's encoder uses one delay for all frames, holds are
expanded: each frame is repeated `hold / gcd(holds)` times and the total
duration is `sum(holds) / 60 * 1000` ms.

## Review loop (not optional)

You are drawing blind unless you look. After every edit:

1. `node tools/spritemaker/sm.mjs render art/aeval/frames/<anim>` and fix every
   `PROBLEM` line before anything else.
2. `node tools/spritemaker/sm.mjs preview <anim>` (or `--frame N`), then
   **Read** `art/aeval/sheets/<anim>_preview.png` and describe what is
   actually there.
3. `node tools/spritemaker/sm.mjs gif <anim> --holds ...` for motion.
4. `node tools/spritemaker/sm.mjs stage <anim>` and Read it: the only true
   test is whether she reads as Aeval at 1x on the platform, in both facings.

A frame that renders as a blob, a floating head, or that does not read as
Aeval at 1x is not done.

## Editing and checking commands

`preview` and `gif` both take a `--fx` flag: with it, they read frames from
`art/aeval/fx/<name>/` instead of `art/aeval/frames/<name>/`. Output paths are
unchanged (`art/aeval/sheets/<name>_preview.png`, `<name>N_big.png`,
`<name>.gif`).

A `<frame>` argument below is either `<anim>/<N>` (meaning
`art/aeval/frames/<anim>/<anim><N>.txt`, or `art/aeval/fx/<anim>/<anim><N>.txt`
with `--fx`) or a path containing a slash and ending in `.txt`, used as given
relative to the repo root.

| command | arguments | what it does | example |
|---|---|---|---|
| `new` | `<anim>/<N> [--from <anim2>/<M>] [--fx] [--force]` | Creates the target `.txt`: 80 lines of 80 dots, or (with `--from`) an exact copy of a source frame that must already validate as 80x80. Creates the folder if missing. Refuses to overwrite an existing file unless `--force` is given | `node tools/spritemaker/sm.mjs new jab/0` |
| `rows` | `<frame> [y0 [y1]]` | Prints rows `y0..y1` (default 0..79; a single `y0` prints just that row) with a column ruler on top and each row prefixed by its zero-padded row number | `node tools/spritemaker/sm.mjs rows jab/0 44 54` |
| `put` | `<frame> <y> <x> <string> [<y> <x> <string> ...]` | Writes each `<string>` into row `y` starting at column `x`, character by character; `_` leaves that pixel unchanged. Rejects the whole call, writing nothing, if any character is not `.`, `_`, or a palette key, or if the placement falls outside the canvas | `node tools/spritemaker/sm.mjs put jab/0 45 30 "##cc##"` |
| `fill` | `<frame> <x> <y> <w> <h> <char>` | Sets every pixel in the `w`x`h` rectangle at `(x,y)` to `<char>` (`.` allowed), clipped to the canvas. Same character validation as `put` | `node tools/spritemaker/sm.mjs fill jab/1 50 44 12 12 a` |
| `shift` | `<frame> <x0> <y0> <x1> <y1> <dx> <dy>` | Moves the inclusive rectangle by `(dx, dy)`; vacated cells become `.`, pixels shifted off-canvas are dropped, destination cells are overwritten | `node tools/spritemaker/sm.mjs shift jab/0 30 45 35 46 2 1` |
| `check` | `[<anim>] [--fx] [--all]` | Validates `art/aeval/anims.json` against the frames/fx on disk: reports `MISSING`/`EXTRA` files, reuses `render`'s validation for `PROBLEM` lines, and for body animations with a `hits` array reports `cover`/`PROBLEM` lines for how much of each hit circle the palette's `water` list covers on the frames active during that hit. With no `<anim>`, checks every body animation (plus every fx with `--fx` or `--all`); with `<anim>`, checks just that one (`--fx` selects the fx table). Exits 1 if any `PROBLEM` was printed, or if a named `<anim>` is incomplete | `node tools/spritemaker/sm.mjs check jab` |
| `import` | `<png> <frame> [--fx] [--anchor feet\|centre] [--force]` | Converts a PNG (80x80 or smaller, RGBA, alpha >= 128 counted as opaque) into a frame `.txt`: every opaque pixel snaps to the nearest palette key by Euclidean RGB distance, then the opaque bounding box is shifted so its bottom row lands on row 67 and its centre column (rounded) lands on column 40 (`--anchor feet`, the default without `--fx`), or so its centre lands on (40,40) (`--anchor centre`, the default with `--fx`). Pixels shifted off-canvas are dropped. Refuses to overwrite an existing `.txt` unless `--force`. Prints the placed box, a per-key pixel count sorted descending, and warns when more than 10% of pixels were far from every palette colour or when any pixel was dropped. A starting point, never a finished frame | `node tools/spritemaker/sm.mjs import art/aeval/sheets/pixler/idle0.png idle/0` |
